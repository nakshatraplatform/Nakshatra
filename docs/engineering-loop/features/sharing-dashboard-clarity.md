## Problem and goal

Approval currently describes draft answers rather than the published approved snapshot. Recent-50 lists prevent managing older requests/grants; read failures appear empty; action errors can sit behind the details dialog. Make these states truthful and manageable while simplifying the personal dashboard.

## Contract and invariants

- AC1: Consent describes the stored approved snapshot, only eligible photos and published horoscope, never unpublished draft answers or owner-only attachments. Missing/malformed review blocks approval; show unpublished-changes guidance.
- AC2: Owners can search/page and manage old pending requests and active/expired grants, including beyond 50 records; use bounded server queries and accurate counts. No unbounded list downloads or per-keystroke database calls.
- AC3: Read failures are errors with retry, not zero/empty success. Failed mutations display inside the active dialog and leave access unchanged.
- AC4: Retain verified-email recipient binding, 15-day expiry, explicit approval, same-origin checks, live sessions, owner scoping, rate limits, immutable audit/outbox, rotation/unpublish behaviour and public-field boundaries.
- AC5: Personal dashboard prioritizes status, attention and sharing access, followed by link controls/history. Preserve Inter/Plus Jakarta Sans, existing tokens, colours/voice and the approved portfolio renderer. No new styling library, Astro migration, B2B changes, PDF work or speculative integrations.
- AC6: Loading, empty, unavailable, long-content, keyboard, light/dark and 320px+ behaviour verified. No claim of production/real-provider verification from local mocks.

## Design basis and affected boundaries

Reuse current atomic decision/grant commands, owner session guard, Zod contracts, request security, disclosure snapshot, modal focus and themed loading feedback. Add an owner-scoped read API for bounded relationship pages; rendering must not manufacture authorization. Preserve legacy RPC contracts for independently deployed clients. Do not duplicate private/public projection rules in browser code.

Verified locations: dashboard page/client; dashboard loader; access summary service; interest decision route/service; existing relationship projection migration; InterestDetailsPanel/InterestHistoryPanel; dashboard-client and access/dashboard service tests; published-dashboard and Complete-access E2E fixtures.

# NAK-103 signed-in UX clarity pass

Mode: compact. Risk: standard, presentation-only. Scope: dashboard activity labels, contextual guidance in the existing portfolio form, readable portfolio narrative wrapping, and grouping of existing account controls. The landing page, publication and verification rules, data model, and API behavior are out of scope.

The owner wants useful ideas from a competitor's form and dashboard without copying its product model. The current editor already supplies examples, audience labels, save status, and previews; the current portfolio already constrains narrative line length. This pass addresses only concrete gaps: an interest list capped at 50 was presented like an exact count; a few ambiguous fields lacked guidance; long unbroken narrative text could overflow; and account data, device, and deletion actions had no visual grouping.

Acceptance: activity labels describe their real scope; optional field guidance does not imply new disclosure or required data; portfolio prose stays readable without truncation; account controls are grouped by purpose on mobile and desktop, with deletion clearly separate; existing action behavior is unchanged. Verify with focused component tests, lint, typecheck, build, responsive browser checks, and diff review. No database or Production operation is needed.

Implementation: the dashboard now labels its capped interest list as latest activity and shows `50+` when the 50-row retrieval cap is reached, while portfolio views state that they are all recorded opens. The form adds hints to education location, career goals, and family origins without changing field contracts. Portfolio narrative text wraps long unbroken content. Account settings groups existing data/device actions separately from deletion and gives reauthentication radio choices their intended compact control style.
